# Glossary

The words we use for Delve, the new application, in its code, its interface and its documents. When two words could
mean the same thing, this file picks one. If a term is missing or unclear, add it here before using it elsewhere.

Status: **agreed** terms were settled with the owner of the project. **Proposed** terms still need a decision.

## Content and play

| Term | Meaning | Status |
|---|---|---|
| **Module** | Written content: a published adventure that was imported (for example from a PDF), or one written in the editor. It holds text, maps, NPCs, encounters and images. A module is canon: play never changes it, and it can be shared. | agreed |
| **Campaign** | One playthrough of a module. It holds everything that changes during play: characters, state, history, and the map state of each map. One module can have many campaigns. | agreed |
| **Campaign status** | Where a campaign stands, set by its host: In progress (the default), Paused, or Complete. | proposed (used since plateau 7) |
| **Session** | One evening, or one continuous span, of play within a campaign. Recaps and XP awards hang off sessions. | agreed |
| **Map** | A map as it was written, part of a module. It never changes during play. | agreed |
| **Campaign map** | A map made for one campaign, such as a district the table invented. It is played beside the module's maps, by the same moves and views, but it is not canon: it belongs to the campaign, never changes the module, never goes into its export, and is gone with the campaign. It may include the module's libraries and exit into its maps. The campaign page calls it "this campaign's own". | proposed (campaign maps, 2026-10-23) |
| **Map state** | One campaign's live state of one map: which rooms and doors are discovered, how each door stands, which secrets are revealed, where the tokens are and where the party is. A map that is new to the campaign starts with a fresh map state. In dungml this is called a "session"; we don't use that word for it. | agreed |
| **Attachment** | A file in a module that its text refers to: an image, or a reference PDF. Every attachment has a description. | agreed |
| **Image** | An attachment that is a picture: a handout, a puzzle, an illustration. Its description tells the DM what it shows and when it fits, and the DM decides when to show it to the players. There are no separate kinds of image. | agreed |
| **Keyed heading** | A heading of a module's text that starts with a key, such as "## 12. The Well Room". It links itself to the room of that key on the text's map. The keyed headings of a text are its room key. | proposed (used since plateau 3) |
| **Conversion** | Making a module from a PDF, or from a request ("a dungeon with kobolds, no plot"), with Claude, in the background. It runs in steps ("Step 2 of 4") and leaves warnings to check. | proposed (used since plateau 5) |
| **Draft** | A module that may not start a campaign until it is marked ready; a conversion can make one. | proposed (used since plateau 5) |
| **Book map** | A page of a converted book that is a map, kept whole as an image (`map-page-<n>`). It is the book's own map, never redrawn. | proposed (used since the walkthrough fixes) |
| **Sketched map** | A map Claude drew in the map language from a text's room key, so that its keyed headings have rooms to link to in play. Its layout is invented, and it says so, naming the book map to compare it with. | proposed (used since plateau 5) |
| **Warning** | Something a conversion, an import or the module itself asks the organiser to check, such as a sketched map or a keyed heading with no room. | proposed (used since plateau 1) |
| **Part** | One text of a module that is a chapter or an area of its own, such as "The Haunted House" or "The Sea Ship". Its keyed headings are its rooms, and its map is drawn for it. The key numbers restart in each part. | proposed (used since faithful modules) |
| **Level** | One floor of a part's map: a book's map page can show several, each drawn as a map of its own, joined by their stairs, hatches and ladders. | proposed (used since faithful modules) |
| **Scoped key** | A room key made unique across parts: as printed ("7") when no other part has it, else the part's short name and the key ("haunted-house-7", "ship-7"). The DM may type either with the part. | proposed (used since faithful modules) |
| **Pregen** | A pregenerated character: a ready-made character of the book (race, class, level, stats, gear, background) that the table may take as its party. The DM makes the party from them when the host asks. The kind's stored name is `pregens`; its default audience is "Players". | proposed (used since faithful modules) |
| **Handout** | One use of an image: a page, letter or picture cut from the book that the players are shown in its room. It is an image attachment linked to its room, never a kind of its own. | proposed (used since faithful modules) |
| **Book-page draft** | A map the organiser has Claude draw from one page of the converted book, level by level, shown beside the page to judge. Keep makes it a map of the module; it replaces the part's sketched map. | proposed (used since faithful modules) |
| **Front matter** | The cover, title page and back cover of a converted book, kept apart as attachments so the DM opens on the first chapter. | proposed (used since faithful modules) |
| **Novel** | A module or a campaign told as a story by Claude, for the install's owner alone: it may tell every secret, private acts and rooms nobody reached included, and no seat sees it, an organiser seat included. It is written in the background as a job (kind `novel`), outline first and then chapter by chapter, read in Delve and printed to PDF from its print page. In Dutch "Roman" (the section is "Romans"). | proposed (used since novelization) |
| **Novelize** | The owner's action, on a campaign's page and under a module's **Novels** tab, that starts a novel: a length, a tone (the DM's tones, or your own), a language (one of the interface's: English, Dutch, French, German or Latvian), optional instructions and, for a campaign, a range of sessions. In Dutch "Romaniseren". | proposed (used since novelization) |
| **Recap** | The shortest length of a novel: one chapter, about 1,500 words. In Dutch "Samenvatting". | proposed (used since novelization) |
| **Short story** | A novel of three to five chapters, about 6,000 words. In Dutch "Kort verhaal". | proposed (used since novelization) |
| **Novella** | The longest length of a novel: eight to fourteen chapters, about 25,000 words. In Dutch "Novelle". | proposed (used since novelization) |
| **Continue** | What the owner does to a novel that failed or was cancelled: the writer keeps the outline and the chapters already written and writes the rest. | proposed (used since novelization) |
| **Carry the party on** | The host's action, on a campaign's page, that takes its party into a new campaign on another module: the chosen PCs as copies with all they own, the party's coin and loot pile and its painted portraits, and a history written by Claude. The old campaign is kept and set to complete. In Dutch "Het gezelschap meenemen". | proposed (used since carry the party on) |
| **Carry on** | Short for carry the party on, used as the verb ("carried on from", "carried on to"). Never "move" or "switch" a campaign's module: a campaign keeps its one module. | proposed (used since carry the party on) |
| **Carried on from / to** | The two links between the old campaign and the campaigns its party was carried on into (a campaign can be carried on more than once); each page shows the other's name as a link. The "to" link remains when the other side is deleted; the "from" is then empty. | proposed (used since carry the party on) |
| **History** | What a carried party takes along: an account of its earlier campaign (who travelled and who died, the people met, deeds, grudges and debts, loot) in two versions, written by Claude as a job of the kind `history` and editable by the host. A campaign has at most one; carrying on again condenses the earlier one, so histories stack. In Dutch "Geschiedenis". | proposed (used since carry the party on) |
| **The DM's history** | The history's full version, with its Loose ends (open quests, unrevealed secrets). The DM reads it every session through `session_primer`, and the host can read and edit it. Never shown to other seats or to Ask. | proposed (used since carry the party on) |
| **The table's history** | The history's version for everyone: it holds only what the whole table was told. Private acts, lines told to some seats, DM notes, unrevealed secrets and exact faction reputation are removed from the material before Claude writes it, never left to the prompt. Ask the DM reads it, and every seat sees it on the play screen's **History** tab. | proposed (used since carry the party on) |
| **Loose ends** | A section of the DM's history only: quests left open and secrets the party never uncovered. | proposed (used since carry the party on) |
| **Write again** | What the host does to a history that failed or that they want redone: Claude writes both versions anew from the old campaign. An edited history asks first, because the edit is replaced. | proposed (used since carry the party on) |
| **Fix-it comment** | What an organiser writes on a module's page about something to fix, in plain words ("exit X is not yet in place, fix it"), optionally tied to a map, a room, a text or an entity. A background job acts on it and proposes a change, which the organiser sees and keeps (a new revision of the module) or rejects; nothing is saved before Keep. Its status: **Open**, **Working**, **Ready to review**, **Kept**, **Rejected**, **Failed** (with its reason, and Retry) or **Closed** (without running). Not the remarks under a conversion's questions, which go into "Notes from making this module". | proposed (table voice and fixes, 2026-10-25) |
| **Comments** (on the PDF form) | What the organiser tells Claude with a book to convert ("the room key starts on page 40", "keep the book's spelling"), kept on the job and given to every prompt of the conversion. | proposed (table voice and fixes, 2026-10-25) |
| **Closed** (a question or doubt) | A conversion's question or doubt the organiser has dealt with: closed ones fold away on the module's page, and every organiser sees the same. Closing only hides; it changes neither the notes nor what the DM is told. It can be reopened. | proposed (table voice and fixes, 2026-10-25) |

## Rules and world

A campaign is set up from four separate things: the module it plays, a ruleset, a setting, and the house rules chosen for it.

| Term | Meaning | Status |
|---|---|---|
| **Ruleset** | The game system and its reference data: rules, classes, races, monsters, spells, items. Today only AD&D 2nd edition exists. | agreed |
| **Rulesets** | The area, in the nav, where the book of a ruleset is looked up: spells, items, classes, ability scores, proficiencies and the turning table, and monsters for organisers only. Every seat reaches it from the play header's "Rulesets" link (a new tab); the nav, `g b` and the command palette are the organisers'. Never "Rules" or "Reference" for the area; the reference store is its source. | agreed (owner, 2026-10-22) |
| **Setting** | The world a campaign plays in, with its gazetteer and lore (for example Greyhawk). A setting is independent of the ruleset and of any module. Its shipped data (the reference's wiki, facts and calendar) is read-only; what the install adds is laid over it. In Dutch "Wereld" (the area is "Werelden"), in German "Welt" ("Welten"), so it is not read as the app's settings. | agreed |
| **Settings** | The sidebar area, for organisers, where the install's settings are read and grown: Lore (search and browse the pages), Facts, Maps, Calendar and Proposals. It shows DM-only content, marked. A player seat never opens it: it reads its campaign's setting in the play screen's **Setting** tab, read-only and without DM-only content. Settings is only ever the game worlds, never the install's options (those are **Preferences**). | agreed (owner, 2026-10-19) |
| **Pack** | A ruleset or a setting installed on this Delve as a folder of its own, travelling as one `.delvepack` file. Organisers download one in Preferences' **Packs**; the owner alone installs, updates or removes one there (or with `delve pack`), as a pack holds code that runs on the server. Delve uses what changed once it restarts: "Restart Delve now", the owner's, when systemd runs Delve with its socket. In Dutch "Pakket". | proposed (DEL-366) |
| **A setting's additions** | What this install put over a setting's pack: the pages added or overridden, its facts and its own world maps with their pictures, DM-only content marked so. An organiser exports them as a file from the setting's **Export and import** tab, and imports such a file there, keeping or replacing the pages and maps of the same title or name. A campaign's proposals stay behind. | proposed (DEL-366) |
| **Setting page** | One page of a setting's lore: a place, a realm, a deity, a person, an organisation…, with its fields and its text, linked to other pages as `[[Title]]`. It is the shipped wiki's page, an addition, or a proposal. A page is found by its title, ignoring case and spacing, and through the shipped wiki's redirects. | proposed (used since Settings) |
| **Addition** | What the install adds to a setting, in Delve's own database: a new page, an override, or a fact. A `make install` rebuild of the reference loses none. Every reader (the DM's lookups and search, Ask the DM, "Did you know", Settings and the Setting tab) reads the setting through the one setting layer, with the additions over the shipped data. | proposed (used since Settings) |
| **Override** | An addition that has a shipped page's title: it replaces that page's text and fields for every reader. It is matched by title, through the redirects, so it is stored under the shipped page's own title. Reverting it brings back the book's page. A DM-only override is the DM's version: seats keep reading the shipped page. | proposed (used since Settings) |
| **Proposal** | What the DM proposes to the setting during play: a new page, an edit of a page (appended, or replacing its text) or a fact. It holds in its own campaign at once, and in every campaign only once an organiser accepts it, when it becomes an ordinary addition. A rejected proposal stays its campaign's own, so that table's world holds. One campaign's pending proposals for the same page merge into one; facts never merge. | agreed (owner, 2026-10-19) |
| **DM-only** (setting content) | Setting content only the DM and organisers see: a page, a section of a page's text (the lines between `::: dm` and `:::`), a fact, a proposal, or a world-map feature tagged `hidden`. It never reaches a seat by any path: the Setting tab, a search snippet, a fact list, Ask the DM, "Did you know", a map's label or a tile. For a DM-only page a seat reads the book's page of that title, or nothing, and no proposed edit makes one; an edit the DM proposes of a DM-only page is DM-only itself. The DM's lookups mark what is DM-only, so it is never narrated. The shipped wiki is public lore and is never DM-only. | agreed (owner, 2026-10-19) |
| **House rule** | One change to the ruleset that the owner likes to play with, for example lizardfolk as a playable race, maximum HP at character creation, or rolling 4d6 and dropping the lowest die for ability scores. A house rule's **DM Notes** section (a heading of those words, at any level) is for organisers: it is cut from the rule for everyone else, in Rulesets and wherever a seat reads the rule. An item, class or race rule also shows in Rulesets beside the book's. | agreed |
| **House-rule bundle** | A named group of house rules that is chosen as one, for example "my usual table". | agreed |
| **Initiative mode** | How a campaign's fights roll initiative, set by the host on the campaign page: **per combatant** (the default; each rolls d10 plus its weapon speed or casting time) or **per side** (the PHB's standard method: one d10 per side, the lower acts first, ties at once). A change takes effect at the next round. | proposed (table voice and fixes, 2026-10-25) |
| **Ongoing action** | A long action a combatant is busy with in a fight: casting a spell, reading a scroll, drinking a potion, using a magic item, or another action that takes time. It runs from its start to the count (or the round) it completes on, carries over rounds until it completes, and can be **interrupted** (damage, a failed save, or the DM's ruling), which says why ("Mirela was hit; *Sleep* is lost"). | proposed (table voice and fixes, 2026-10-25) |
| **Interrupt** | What ends an ongoing action before it completes: damage taken, a failed save, or the DM's ruling (`interrupt` tool). The action is lost, and the timeline says why. The `combat_round` call can interrupt one by its own rules. | proposed (table voice and fixes, 2026-10-25) |
| **Initiative timeline** | The strip above the story during a fight: the round, and each combatant at the initiative count it acts on, with its ongoing action drawn as a span. The order shows once the round's initiative is rolled; the round's outcomes only once the DM's text for it has arrived. Unseen monsters stay unnamed. | proposed (table voice and fixes, 2026-10-25; the owner's word in backlog Interface 9) |

House rules and bundles are written in the editor and chosen when a campaign is created, so the DM applies them without being reminded.

## The world (plateau 6)

| Term | Meaning | Status |
|---|---|---|
| **World map** | A map of the land outside the dungeon, in km: terrain cells (on a picture's grid, or Delve's own squares), places, routes, water and regions, kept as GeoJSON over an optional picture. It is imported from a GeoJSON file or read from a picture of a map with its key, then reviewed. A module or a setting brings one, and a campaign gets its own copy. The party has one place on it, and the players see only what is known. (Plateau 6's maps, in ttrpg2's `.map` language, are converted.) | proposed (used since plateau 6; rewritten in plateau 7) |
| **Travel**, **journey** | Going overland from the party's place to another on a world map, a day at a time, at the pace of the slowest traveller, the mode, the terrain and the weather. A journey is one or more legs, and stops early when an encounter comes. | proposed (used since plateau 6) |
| **Terrain** | What a world map's cell is: plains, forest, hills, mountain, swamp, desert, arctic, jungle, urban, sea, lake or impassable. It sets how fast a party crosses the cell, and the weather's terrain. | proposed (used since plateau 7) |
| **Region** | A named area on a world map, such as a kingdom or a forest's name. Revealing a region makes all its land known. | proposed (used since plateau 7) |
| **Route** | A road, track or trail on a world map. A route is faster than the land it crosses, crosses rivers and passes, and is cut at the edge of what the party knows on the players' map. | proposed (used since plateau 7) |
| **Mode** | The way a party travels a leg: on foot, on horseback, by cart, by river boat, or by ship. Each has its pace and goes where it can: the land and its routes, the rivers and lakes, the sea and the large lakes. | proposed (used since plateau 7) |
| **Leg** | One part of a journey, by one mode, from the party's place to one destination. A journey of several modes is several legs: ride to the port, then sail. | proposed (used since plateau 7) |
| **Review** | The organiser's check of a world map read from a picture, before it is used: the doubtful readings decided and every colour given a terrain (or "outside the map"). A map in review is no player's. | proposed (used since plateau 7) |
| **Known** | Of a world map's land or feature: what the party has seen or heard of. Knowledge is the campaign's, shared by its seats; the party learns land by travelling, and the DM can reveal or hide more. | proposed (used since plateau 7) |
| **Fog** | How a world map shows the land the party doesn't know: covered, with nothing in it sent to the players. | proposed (used since plateau 7) |
| **The setting's map** | A world map the setting owns on this install, beside the maps modules bring: imported from GeoJSON, read from a picture (then reviewed), or copied from a module's map ("Copy to Greyhawk's maps"). A new campaign copies the module's maps first, then the setting's ready ones (the module's wins a name clash); the setting's built-in map only while the install has no ready map of its own for it. A campaign made before keeps its own copies. In Settings it is shown whole, hidden features marked; a seat sees it whole too, but never a hidden feature or the DM's notes. | proposed (used since plateau 7; rewritten in Settings) |
| **Calendar** | The setting's months, festivals and seasons; in Greyhawk the Common Year (CY). A campaign without a setting has a plain calendar ("Day 12"). | proposed (used since plateau 6) |
| **Date** | A campaign's day on its calendar, such as "4 Planting 576 CY" or "Richfest, day 4, 576 CY". It is derived from the campaign's day and start date, never set by hand. | proposed (used since plateau 6) |
| **Season** | Part of the year, derived from the date: Greyhawk's own (Low summer, Midwinter) and the weather's (winter, spring, summer, autumn). | proposed (used since plateau 6) |
| **Weather** | A day's weather in one terrain, rolled the first time it is asked for that day and kept. Its pace slows travel; a blizzard stops it. | proposed (used since plateau 6) |
| **Faction** | A group with goals in the campaign, from the module or added in play. The DM sees its notes, strength and reputation; the players, once they know of it, see only its standing. | proposed (used since plateau 6) |
| **Standing** | The word the players see for a faction's view of the party, from its reputation: Devoted, Friendly, Cordial, Neutral, Wary, Hostile, Sworn enemy. | proposed (used since plateau 6) |
| **Clock** | A faction's plan in motion, for the DM only. A countdown clock loses a day with each new day; a progress clock fills its segments only when the DM advances it. When it completes, its consequence happens in the world. | proposed (used since plateau 6) |
| **Quest** | Something the party may take on, with a giver, stakes and a status (available, active, paused, complete, failed). The players see a quest once it is known, with the notes the DM marks known. | proposed (used since plateau 6) |
| **Lore fact** | A short fact of the setting, such as those the play screen shows as "Did you know" while the DM thinks: the shipped ones, the install's own (added in Settings), and the campaign's proposed ones. A campaign's own facts, established in play with `add_fact`, are the DM's. | proposed (used since plateau 6) |
| **Merchant** | A seller of magic items in a settlement, whose shelf is rolled once and kept until restocked. Only the DM sees the shelf, and narrates it. | proposed (used since plateau 6) |
| **Portrait** | A character's or a possession's picture. A free one is portraitgen's, drawn by the browser from a description and a seed; a paid one is painted. | proposed (used since plateau 6) |
| **Scene** | A painted picture of a moment in play, which lands in the story when it is done. It needs paid images. | proposed (used since plateau 6) |
| **Paid images** | A campaign's switch, off until the host turns it on, that lets the DM have pictures painted by a paid provider. | proposed (used since plateau 6) |

## Things characters have

| Term | Meaning | Status |
|---|---|---|
| **Inventory** | The items a character carries. Encumbrance is computed from it. | agreed |
| **Spell loadout** | The spells a character memorizes by default. During play the app tracks which are memorized and which have been cast. | agreed |
| **Possession** | Something larger than an item that a character or the party owns: a mount, a vehicle, a ship, a house, a stronghold, a domain. All possessions are handled the same way and can have a portrait; a mount's or a vehicle's movement sets the pace of travel. | proposed (used since plateau 6) |

## People and roles

| Term | Meaning | Status |
|---|---|---|
| **DM** | The Dungeon Master. It is always Claude, never a person. | agreed |
| **Player** | A person playing in a campaign. Each player has their own screen and their own language, and can join or leave at any time. **Players see each other's sheets** (owner decision 4, faithful modules): that is the current rule, and nothing hides one player's sheet from another. What stays hidden is the DM's: module text, secrets and notes. | agreed |
| **Host** | The player who started a campaign, usually by choosing its module. The host sets the table's options (such as the beat timer), and can always carry on alone when the others leave. | agreed |
| **Co-host** | A player the host has given the host's rights, such as setting the table's options. | agreed |
| **Observer** | A person who watches a campaign and can use table talk and ask the DM questions, but takes no actions and controls no characters. | agreed |
| **Seat** | One person's place at one campaign's table: a name, a language and a role (host, co-host, player or observer). Joining by the table's join link gives a seat, and its rights are in that campaign only. An account's seat follows it to any device. The install's owner has a seat at every table, as its host at first. "Only you" in the story means only this seat. | proposed (used since plateau 4) |
| **Join link** | A campaign's link (and QR code) that gives whoever opens it, once logged in or with a new account, a seat at its table. The host can make a new one, and the old one stops working. | proposed (used since plateau 4) |
| **Organiser** | A person who may create and import modules, edit house rules, add to the settings in Settings and decide the DM's proposals, change Preferences, read the DM log and the DM's map, and start campaigns on this install. The install's owner is always an organiser, and only the owner can make a seat or an account one. Being an organiser is separate from a seat's role at a table: the host of a table needn't be one. | proposed (used as defined since plateau 4) |
| **Account** | A person's login on this Delve: a username and a password, made through an invite, by an organiser, or by a sign-up the owner or an organiser approved (there is no email). It holds their profile and their seats at every table. It may be an organiser, or hold the owner's rights. | agreed (owner, 2026-10-24; sign-up 2026-10-26) |
| **Sign-up** | Asking for a player's account oneself, at `/sign-up`, while the owner or an organiser has opened it on the Players page. The account is **pending** ("waits for approval") and can't log in until it is **let in**; **turned away**, it is deleted. Logging in on a table's join link lets it in. In Dutch "Aanvragen" (an account "aanvragen", "binnenlaten", "weigeren"). | agreed (owner, 2026-10-26, DEL-156) |
| **Profile** | What a player shows of themselves at their tables: display name, pronouns, avatar, colour and about me; the hosts also read their note for the host and time zone. Never their character's portrait. | agreed (owner, 2026-10-24) |
| **Tavern** | Table talk full screen, in place of the story: it opens by itself before an evening's first act, while the players arrive. It is not a lobby: it is the table's own talk, and the DM never gets it. | agreed (owner, 2026-10-24) |
| **Character** | An in-game persona controlled by a player (a PC). A player can control several characters: playing alone, one player often runs a whole party. | agreed |
| **NPC** | A non-player character, played by the DM. | agreed |
| **Party** | The characters in a campaign who adventure together. | agreed |
| **Leave the party** | A PC leaves the party without being deleted, because it **died**, **retired** or **left**. It drops out of the party sidebar and Acting for, keeps its sheet, history and place in the story, and is listed folded by its reason ("Fallen: Tansy", "Retired", "Left"). The DM or an organiser can bring it back (**Return**). Not a seat leaving the table. | proposed (table voice and fixes, 2026-10-25) |

## Turns and language

| Term | Meaning | Status |
|---|---|---|
| **Beat** | One go of the table. Every player present submits an action or passes, and the DM resolves them together. Single-player play is a beat with one player in it. While a player is typing, the others see a progress indicator. | agreed |
| **Round**, **turn** | The AD&D 2e units of game time: a combat round is one minute, a turn is ten minutes. They are never used for a go of the table. | agreed (2e rules) |
| **Beat timer** | An optional limit, set by the host, on how long players have to enter their action in a beat (for example 3 minutes). When it runs out for a player, the host's choice applies: the character either holds back for that beat, or the DM plays a cautious in-character action for them. | agreed |
| **Hotseat** | Several people playing at one screen, the host's: the host turns it on in the host's options and names the players there, each with the characters they play. In a beat each of them takes a turn at the Act box ("Anna's turn", then "Pass the screen to Ben."), and the beat waits until all have; the DM and the story name each act's player. Nothing on a shared screen is for the DM alone. A seat at its own screen plays beside them as always. | proposed (DEL-365) |
| **Act** | Sending an action into the beat. It is resolved by the DM and can change the world. | agreed |
| **Pending act** | An act sent in a beat that hasn't closed yet. The table sees the others' pending acts as drafts, and a seat can change its own until the beat closes. | proposed (used since plateau 7) |
| **Private act** | An act marked "Only the DM": the other seats never see it, and the DM answers it to that seat alone. A pass can't be private. | proposed (used since plateau 7) |
| **Table talk** | What the people at a table, players and observers, say to each other. Everyone at the table reads it, each in their own language; the DM never gets it, and it has no effect on the world. An Ask the DM answer can be shared into it. | proposed (used as defined since plateau 4) |
| **Hold back** | The beat timer's default fallback: a character nobody acted for does nothing this beat. | proposed (used since plateau 4) |
| **In character** | The other fallback: the DM plays a cautious action for a character nobody acted for (keep watch, follow the party), with no spell, charge or fight. | proposed (used since plateau 4) |
| **Present** | At the table now: a seat is present while its screen is open (listening to the event stream), or was in the last 30 seconds. Only present seats hold a beat up. | proposed (used since plateau 4) |
| **Tool row** | One line in the story for a tool the DM used during a beat ("saving_throw"). Only the host and co-hosts see tool rows, and only the host sees a refused one; the other seats see what the characters perceive. | proposed (used since the walkthrough fixes) |
| **Ask the DM** | An out-of-band question to the DM ("what's a kobold?"). It is answered privately from the rules, the setting and what the asking player's characters know, and it never changes the world. | agreed |
| **Base language** | English. Modules, campaigns, rules and all stored state are in English. Translation happens only at each player's screen, for what they type and what they read. | agreed |
| **Voice** | Talking aloud at the table, relayed through Delve to the other people in voice, never to the DM, and never recorded. Nobody is in voice until they press **Join voice**; the campaign's host can switch voice off. | proposed (table voice and fixes, 2026-10-25) |
| **Listening only** | In voice without talking: a seat with no microphone, one that refused it, a browser that can't encode speech (Safari and every iPhone browser for now), or an observer. | proposed (table voice and fixes, 2026-10-25) |
| **Muted** | In voice, but with the microphone switched off by the person's own choice (**Mute**): their frames are not sent. Unlike listening only, they can unmute. | proposed (table voice and fixes, 2026-10-25) |
| **Retry** | Playing a beat that failed for a reason that may pass (the usage limit, a crash, a restart) again with the same acts. Only the latest beat, before anyone acts again; what the DM already applied is not undone, and the DM is told it. | proposed (table voice and fixes, 2026-10-25) |

## Words we avoid

| Avoid | Use instead | Why |
|---|---|---|
| "session" for the state of a map | map state | "Session" means an evening of play. |
| "campaign" for written content | module | Campaign means a playthrough. |
| "owner" for the player who runs the table | host | The host runs the table; "owner" sounds like file permissions. |
| "GM" | DM | One word for the role. Claude is the DM. The stored audience value `gm` is data, not a word people read (`docs/data-dictionary.md`). |
| "round" or "turn" for a go of the table | beat | Round and turn are 2e game time. |
| "turn" for a day | day | A turn is ten minutes of 2e game time; travel and the clocks count days. |
| "hex" | world map, place, cell | Only of a picture's grid ("1 hex = 30 miles"): Delve's world maps are in km, and their cells are terrain, not a hex game board. |
| "chat" | table talk | Table talk is the table's own word, and keeps it apart from what goes to the DM. |
| "user" for a person in the interface | player, account | "Account" is the login (a username and a password); a seat is a place at one table, and an account's seat follows it. |
| "session" for a login | "logged in", "Where you're logged in" | "Session" means an evening of play. The stored logins are `login_sessions`. |
| "asset" or "handout" in the interface | attachment, image | "Asset" is the `.dscn` format's word; a handout is one use of an image, not a kind. |
| "map plate" or "map image" for a book's map page | book map | One word for the book's own map, apart from a sketched map. |
| "Settings" for options | Preferences (the install's), Table options (a campaign's) | Settings is the area for game worlds (owner decision 1, 2026-10-19); one word, one meaning. |
| "theme" or "skin" | look | One word for the per-browser choice; "theme" stays the editor's word for Monaco's colours, in code only. |
| "voice chat" | voice | "Chat" is avoided (table talk is typed); voice is its own word. |
| "delete" or "remove" for a PC who died or retired | leave the party | Delete is for real mistakes; a PC who leaves keeps its sheet and its place in the story. |
| "tracker" or "strip" for what the table sees of a fight | initiative timeline | The tracker is the DM's fight state; the timeline is the table's view of it. |
