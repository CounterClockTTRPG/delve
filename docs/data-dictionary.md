# Data dictionary

The values Delve stores and exchanges: in the database, in the API's JSON and in `.dscn` files. The glossary
(`docs/glossary.md`) picks the words people read; this file picks the values code writes. When the two differ, the
interface shows the glossary's word for the stored value.

## Values

| Field | Values | Where | Shown as | Notes |
|---|---|---|---|---|
| `audience` | `gm`, `player` | module texts and their sections, attachments, entity records (NPCs, encounters, factions, quests, rumors, secrets), in the database, the API and `.dscn` | "DM only", "Players" | The `.dscn` format's values, used everywhere so nothing is mapped (owner, 2026-10-18). `gm` is the default. The API refuses anything else with 422, `dm` included. Migration `0008_audience_gm` rewrote the `dm` that plateau 3 first stored. |
| `beats.status` | `open`, `running`, `done`, `failed`, `cancelled` | the `beats` table, `play/state`'s `beat` and the `beat` event | the thinking indicator while `running` | A beat is `open` from its first submission while it waits for the table (plan 4 Task 4), and `running` from its closing while the DM answers; solo play goes straight to `running`. At most one beat per campaign is `open` or `running`. The `beat` event carries `{beat_id, status, submitted: [seat ids], deadline}`, never the texts. |
| `characters.controller_id` | a seat id, or null | the `characters` table | the seat's name | The seat that plays the PC (plan 4 Task 1); null when nobody does, and for NPCs. A seat that leaves, or becomes an observer, frees its characters. Migration `0010_seats` gave every existing PC to its campaign's owner seat. |
| `conversions.kind` | `pdf`, `generate`, `worldmap`, `dungeon-map`, `book-map`, `novel`, `history` | the `conversions` table and the API's conversion JSON | "A PDF", "Describe the module you want"; "From a description", "From the book's map" for a draft | A conversion of a PDF, or a module generated from a request (plan 5 Task 4). Plan 7: a world map read from a picture (`worldmap`, its `target` `{module_id | campaign_id | setting_id, name, title}`, its `result` `{…target, picture, doubts}`; settings plan Task 9 added `setting_id`, a setting's own map, whose job publishes `setting` instead of `world`), and a dungeon map's draft from a description or a book's map page (`dungeon-map`, `book-map`, the draft in its `result`). These three make no module, and are open text, as the column is. A `generate` job asked for pictures (DEL-347) has `pictures` (the limit, 1 to 12) and `owner` (whether the owner asked) in its `target`, and its last step is `painting`: at most that many player attachments on the made module, each failure a `picture-not-painted` warning. |
| `conversions.mode` | `ready`, `draft` | the `conversions` table and the API | "Ready to play", "A draft to work on" | The module it makes is a draft (`modules.draft`) or ready. Anything else is refused. |
| `conversions.status` | `queued`, `running`, `paused`, `done`, `failed`, `cancelled` | the `conversions` table, the API and the `conversion` event | "Queued", "Running", "Paused" on the Conversions panel | At most one is `running`. A job left `running` by a Delve that stopped becomes `failed` with "Delve stopped during the conversion.", except a thorough conversion (its `target` `{"thorough": true, "folder"}`, thorough conversion Task 4): it becomes `paused`, its job folder `<data dir>/conversions/<id>/` kept, and so it does at the usage limit (resuming by itself after the reset) and on an error outside a piece (`error` set). A paused job holds no slot and resumes from its first unfinished piece; it never ends `failed`, and its cancel deletes its folder. **`queued`** (thorough conversion, owner addition 2026-10-23): a PDF uploaded while another job runs, while the queue is paused, or while others wait; it holds no slot, its `target` keeps its book (`upload`, a path in `<data dir>/uploads`, and `book_maps` for a quick one), and it becomes `running` by itself, oldest first by `created_at`, when the slot frees (a job ends, is cancelled or pauses). A resumed paused job is `queued` again, and so is every job Delve's stop paused, at the next start. A queued job whose book is gone at the start fails with "Delve stopped while the conversion was queued, and its book was lost.". A paused-by-hand job's `paused.reason` is `paused by the organiser`. Any other kind of job is still refused (409) while one runs. |
| `join_requests.status` | `pending`, `accepted`, `declined`, `withdrawn` | the `join_requests` table, `GET /api/account/requests`, `GET /api/campaigns/{id}/requests`, the `join_requests` event | "Waiting for the host", "Accepted", "Declined", "Withdrawn" | An account's request to join a public table (DEL-204 part B). At most one `pending` per account and table; the host or a co-host accepts it (a `player` seat, `seat_id`) or declines it; the player withdraws it. Its `messages` are the thread between them, for people only: never in a DM prompt. Migration `0031_join_requests`. |
| `settings` key `conversion-queue` | `{"paused": true \| false}`; absent is not paused | the `settings` table (its own row, not the app's settings), `GET`/`PUT /api/conversions/queue` (`paused`), the `conversion-queue` event | "Pause the queue", "Unpause the queue" | The conversion queue's switch (owner addition 2026-10-23, design d1 option A): while paused, no queued job starts and no paused job resumes by itself (they wait in the queue); a running job runs on. | `conversions.questions.doubts[].kind` | `missing-text`, `missing-room`, `checker-flag`, `left-out`, `guessed-landing`, `picture-unsure`, `crop-refused`, `sketched-map`, `other` | the `conversions` table (`questions`) and the API | | Thorough conversion Task 6: a thorough job's doubts, each `{piece, part, pages, kind, text}`, gathered from its job folder's `doubts/*.json` (`thorough.doubts.gather`).
