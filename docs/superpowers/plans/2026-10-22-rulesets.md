# Delve: Rulesets, implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a Rulesets area where every seat looks up the ruleset's spells, items, classes, ability scores,
proficiencies and turning table (and the owner and organisers its monsters too), with the campaign's homebrew beside
the book's entries.

**Architecture:** The reference store gains filter tables at build time and paged browse queries. A rulebook in
`delve.rules.adnd2e` turns them into sections, rows and entries. A view in `delve.play` gates monsters, adds the
campaign's house rules and cuts their DM notes. A thin router under `/api/rulesets` serves it. The web app gets the
area's four screens. A seat may leave its table for this area only, through a link in the play header that opens a
new tab.

**Tech Stack:** Python 3.12, FastAPI, sqlite3 (the read-only reference store), React 18 + TypeScript + React Query,
cmdk, vitest, Playwright. No new dependency and no migration of `delve.db`. `reference.db` is rebuilt (`make install`
runs `delve reference build`).

**Spec:** `docs/superpowers/specs/2026-10-22-rulesets-design.md` (67f668c). Its owner decisions 1–9 stand.

## Global Constraints

- **Earlier plans still apply:** `GUILD.md`, and the Global Constraints of plateaus 0–7, faithful modules, settings,
  portraits and images, novelization, looks and banners, Carry the party on, and Open fixes and PC names.
- **Every task leaves `make ci` green on its own,** tests first, one commit per task with the message given.
- **Monsters need the organiser role** (`"organiser" in principal.roles`), not the absence of a seat. For anyone
  else, the monsters section, its rows, its entries, its facets, its count and its search hits don't exist: the
  answer is the same 404 as for an unknown section or id, never a 403 that names a monster.
- **A house rule's `## DM Notes` section never reaches a reader without the organiser role.** The server cuts it.
- **A seat sees only its own campaign's house rules,** as `delve.play.house_rules.effective_rules` gives them.
- **The reference store is read-only at run time.** New tables and columns are made by `delve reference build`.
- **Never copy ttrpg2's code** (backlog 29). Its page list, filters and rarity bands are the reference here.
- **UI strings:** every new string is in both `web/src/i18n/en.json` and `nl.json`, under a `rulesets.` prefix. The
  book's entries stay in English. Dutch: "Regelsets" for the area, "Spreuken", "Monsters", "Voorwerpen", "Klassen",
  "Vaardigheidsscores", "Vaardigheden", "Ondoden verdrijven", "Rassen", "Huisregel".
- **Phones:** every new screen works at 390 px wide with no sideways scroll, like the other areas.

## Review Focus

1. **A seat reaching a monster by a side door:** the search box, the palette, a pasted `/rulesets/adnd2e/monsters/12`
   address, a section count, an item whose text links a monster. Each gets "not found" or nothing. (Task 5,
   `test_a_player_never_meets_a_monster`.)
2. **A spell of a compound school** ("Alteration/Necromancy", "Enchantment, Necromancy") listed under School =
   Necromancy, and a `Wizard` (capitalised) spell under Caster = wizard. (Task 2,
   `test_spells_page_splits_compound_schools`, `test_spells_page_caster_ignores_case`.)
3. **Two spells with one name** (a spell for both casters is two rows): both listed, each with its own page. (Task 2,
   `test_same_named_spells_have_their_own_ids`.)
4. **A house rule whose DM notes are spelled differently** ("## DM notes", "## DM Notes" as the last section, none at
   all, "### DM Notes" under another heading). The cut matches the heading's words without case, at any level, up to
   the next heading of that level or higher. A rule without the section shows whole. (Task 4,
   `test_dm_notes_are_cut`.)
5. **An install whose `reference.db` predates this plan.** `delve serve` refuses to start, as for other snapshots,
   and says to run `delve reference build`. It must not crash later on a missing table. (Task 1,
   `test_an_older_build_is_stale`.)

## Decisions taken in this plan

1. **API under `/api/rulesets`, global, with a reader dependency** (the spec leaves it open). A seat's campaign comes
   from its seat; an organiser without a seat may pass `?campaign=<id>` to see that campaign's house rules. A seat's
   `?campaign=` is ignored. A seat that has left gets 403 `LEFT`, as at its table.
2. **Sections and their keys:** `spells`, `monsters`, `items`, `classes`, `abilities`, `proficiencies`, `turning`,
   `races`. `abilities`, `proficiencies` and `turning` are **tables** (their section page shows the table itself).
   The others are **lists** with an entry page each. `races` exists only when the reader's house rules give a race.
3. **Entry ids:** the book's row id as a string (`"412"`). The abilities use their name (`"strength"`). A house rule's
   entry is `"hr-<rule id>"`.
4. **Monster filters, normalised at build time** into `monster_facet(monster_id, facet, value)`:
   - `size`: every standalone T/S/M/L/H/G letter before the first "(" (`"M (6' tall)"` → M; `"S to M"` → S and M);
   - `alignment`: the nine codes LG…CE from words or codes ("Neutral (evil)" → NE, "N" → N), `any` for "Any…" or
     "Varies", `none` for "Nil" or "None", `other` for anything else non-empty;
   - `terrain`: any of `arctic, desert, forest, hills, jungle, mountains, plains, swamp, water, subterranean, urban,
     planes, space, any`, matched from words (water: aquatic, ocean, sea, lake, river, fresh, salt, underwater;
     subterranean: underground, underdark; planes: abyss, hells, plane, planes, astral, ethereal; space: wildspace,
     phlogiston, space; any: "Any" with no other terrain word). Anything else non-empty → `other`;
   - `book`: each `categories` entry with its " Creatures" suffix dropped, leaving out the bare "Creatures".
5. **Spell schools at build time** into `spell_school(spell_id, school)`: `school` split on "/", "," and " and ",
   trimmed, in title case.
6. **Item rarity bands**, after ttrpg2's labels: common ≤ 5, uncommon ≤ 20, rare ≤ 40, very rare ≤ 55, legendary
   ≤ 70, artifact above. The filter is one band. Item types show as stored, with the snake_case mundane types in
   words through i18n keys (`rulesets.itemType.misc_equipment` → "Miscellaneous equipment").
7. **A build version** in `meta` (`build INTEGER`, `BUILD = 2` in `build.py`). `open_reference` treats a different or
   missing build like other snapshots: `ReferenceStale`.
8. **Page size 50**, server side (`offset`, `limit` ≤ 200). A list's filters and offset live in the address.
9. **The play header's link** goes to `/rulesets/<campaign's ruleset>` in a new tab (`target="_blank"`,
   `rel="noopener"`), labelled "Rulesets". Everyone at the table sees it.
10. **The palette** (owner and organisers without a seat) gets a "Rulesets" group that asks the search route from two
    characters typed. The `g b` shortcut opens the area.
