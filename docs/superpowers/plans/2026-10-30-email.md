# Email Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Delve sends email (password resets, "You're in" on approval, host mail on Skip/Move and to the table, board
reply notifications) to private, confirmed addresses, through a provider layer with a log-only provider and Emailit.

**Architecture:** A new package `delve.mail`. Senders never talk to a provider: they compose a message in the
recipient's language and put it in an outbox table in the same transaction as what caused it. A background loop in
the app's lifespan delivers due messages through the configured provider (`log` or `emailit`), paced to 2 per second,
resolving the recipient's address only at send time, retrying temporary failures. Addresses, confirmation tokens,
mail switches and board follows are new storage. Email wording lives in the web's i18n dictionaries under `email.*`,
read by the server, so the existing five-language tests cover it.

**Tech Stack:** Python 3.12, FastAPI, SQLite (SQLAlchemy Core, Alembic migrations), httpx, pytest; React + TypeScript,
TanStack Query, Vitest + Testing Library, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-30-email-design.md` (approved 2026-10-30). Read it before any task; this
plan argues from it. Tracking: Tasker DEL-314.

## Global Constraints

- Addresses are private: never in an API answer except the account's own, never in an event, never in a log line,
  never in the outbox table. One email per recipient (one `to`), never cc/bcc.
- Typed-in addresses receive nothing but their confirmation until confirmed. Google's address (only present when
  `email_verified` is true; `Claims.email` is already empty otherwise) is stored confirmed, only when the account has
  no address yet.
- Kinds and their switches: `confirm`, `reset`, `approved`, `test` always go; `schedule` and `host` follow
  `mail_host`; `board` follows `mail_board`. Every switchable email has a one-click off link and `List-Unsubscribe` +
  `List-Unsubscribe-Post: List-Unsubscribe=One-Click` headers; the always-go kinds have neither.
- Every email is in the recipient account's `profile.language` (en, nl, fr, de, lv); words a host or a poster wrote
  are never translated. Text part and HTML part; no remote images, no tracking (`tracking: false` to Emailit).
- Emailit: `POST https://api.emailit.com/v2/emails`, `Authorization: Bearer <key>`, `Idempotency-Key: <outbox id>`;
  retry 429 (honour `retry_after`), 5xx and timeouts; don't retry 400/401/402/403/404/413/422. At most 2 sends a
  second.
- Env `EMAILIT_API_KEY` wins over a saved key, as `REPLICATE_API_TOKEN` does. The key file is written with
  `connections.write_secret` (0600), never read back to the web.
- Sending never blocks a request: routes only enqueue.
- Migrations: plain `op.add_column` / `op.create_table`; never a batch rebuild of `accounts` or `campaigns`. One
  migration for the whole plan, numbered from master at the time (today the next free is `0043`; `0040` was never
  used: don't fill it).
- Every UI and email string in all five `web/src/i18n/*.json` (the i18n tests fail otherwise); help topics translated
  as the others (`help.test.tsx` fails otherwise).
- The shared checkout: work in a worktree branch `feat/email`, check `git reflog` before merging to master.
- No Prettier defaults on web files (no config; don't reformat files).

## Review Focus

1. **A host writes to five players at once:** five outbox rows, one account each, and no answer, event or log line
   carries anyone's address. Test in Task 9.
2. **The provider is down or slow while someone posts a reply, skips a session or asks for a reset:** the request
   answers as fast as without email; the message waits in the outbox. Test in Task 3 (sender) and Task 10 (reply
   with a provider that raises).
3. **A player removes their address, or turns host mail off, after a message was queued:** it is dropped at send
   time, not sent. Test in Task 3.
4. **"Forgot your password?" with an unknown username, a known one without an address, a known one with a confirmed
   address, and a typed address:** the same status and body every time. Test in Task 6.
5. **A lively thread:** five replies before the follower comes back send one email; after the follower opens the
   topic, the next reply sends one more. Test in Task 10.

    `LogProvider()` logs `kind`/account/subject only; `EmailitProvider(key: str, client: httpx.AsyncClient)`;
    `provider_for(app) -> MailProvider` (reads settings each pass; `app.state.mail_transport` for tests, as

  - `outbox.queue(storage, account: Account, kind: Kind, mail: Composed, now: datetime, *, reply_to: str | None = None,
    unsubscribe: str | None = None) -> str | None` — None (nothing queued) when `address_for` is None now;
    `outbox.address_for(account, kind) -> str | None` (`email_pending` for `confirm`, else `email`; None when the

    `outbox.off_token(data_dir, account_id, group: Literal["host", "board"]) -> str` and
    `outbox.read_off_token(data_dir, token) -> tuple[str, str] | None` (HMAC-SHA256 with a secret in file
    `mail-secret`, made on first use with `write_secret`).
  - `sender.send_due(app, now) -> int` (one pass, returns how many it handed to the provider);
    `sender.sender_loop(app, *, tick=2.0)`; `PACE_S = 0.5`; backoff `RETRY_S = (60, 300, 900, 3600, 3600, 3600)` then
    failed `"gave up"`; prunes sent rows older than 30 days once a pass.

Emailit request body: `{"from", "to", "subject", "text", "html", "tracking": false, "reply_to"?, "headers"?, "meta":
{"delve_id": id}}`. Map: 200 → `Accepted`; 429 → `Retry(retry_after or 1)`; ≥500, timeout, connect error → `Retry(60)`;
402 "Emailit has no credits left"; 401 "Emailit refused the API key"; 403 with `unverified_workspace_recipient`
"Emailit's workspace is still in sandbox"; 403 other / 422 "Emailit hasn't verified the sending domain"; others
"Emailit refused the message (HTTP n)" — never the remote body, never the key.
